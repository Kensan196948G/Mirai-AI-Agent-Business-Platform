05

Workflow / State Machine

IDEA --submit--> PROPOSED --approval--> APPROVED --activate--> ACTIVE
ACTIVE --build/test--> STAGING --uat--> PRODUCTION --close--> CLOSED --archive--> ARCHIVED
ACTIVE --suspend--> SUSPENDED --resume--> ACTIVE
  • State TransitionはVersion管理されたWorkflow Definitionで管理。
  • TransitionごとにRequired Role、Required Evidence、Policy、Approval Ruleを紐付け。
  • 未承認TransitionはApplication層だけでなくDomain層でも拒否。

Approval / Policy詳細

Policy Decision Input

{
  actor: "user|agent|service",
  role: "Developer|Reviewer|Approver|Admin",
  action: "github.merge",
  resource: "project:DX-2026-0042",
  environment: "production",
  risk_level: "R4",
  evidence: [],
  context: {}
}
Decision意味
PERMITそのまま実行可能
DENY実行禁止
APPROVAL_REQUIREDApproval Request生成、承認後のみ実行
Approval Action、Policy Decision、Tool Call、Release操作は全てAudit対象。Audit EventはUPDATE/DELETEしない。

10

Security設計

Identity

authentik + OIDC。User/Service/Agent Identityを分離。

Network

Tailscale経由。DB/Grafana/Runnerの直接Internet公開禁止。

Secrets

Repository/Notion/Slack/Logに保存しない。

Sandbox

Runnerは最小権限、Filesystem/Network/Tool Permissionを制限。

Redaction

Token/Password/API Key候補をLog前にMask。

Supply Chain

Dependency/Secret/Container ScanをCIへ。

Error Handling / Retry

種別戦略
AI Provider 429/5xx指数Backoff + Provider/Model切替候補
Notion/GitHub/Gmail一時障害Retry + Idempotency + Dead Letter相当記録
Validation ErrorRetryしない。Failed/Blockedへ
Policy DenyRetry禁止。理由表示
Approval PendingBlockedで待機
