MIRAI-AGENTOS / AI DEVELOPMENT GOVERNANCE

開発フェーズ別 AI 分担ガイド

Claude Code、Codex、DeepSeek Harnessを同じフェーズ内で混在させず、フェーズごとに主担当AIを固定し、Gateで成果物を次のAIへ引き渡す運用モデル。

原則分担表全体フローP0-P11役割運用ルール
01

基本原則

同じフェーズで3つを混ぜない。 フェーズごとに主担当AIを固定し、成果物とGateを明確にして次のAIへ引き渡す。

04

P0〜P11 詳細

P0

要件・Architecture確定

Claude Code
  • 要件定義書・詳細設計仕様書・AgentOS技術設計概要を読み込み、実装前Architectureを確定。
  • Requirements / Architecture / Repository Boundary / Technology Stack
  • Directory Structure / Data Model / API Boundary / Agent Boundary / Security Boundary
  • docs/、architecture/、ADR、README、CLAUDE.md、CODEX.mdを固める
Gate：Architecture矛盾なし、SoR定義済み、PostgreSQL境界確定、Agent/Model分離確定、Approval設計確定。
P1

基盤構築

Claude Code
  • Repository構造を作成：apps / kernel / agents / skills / integrations / database / tests / docker
  • Docker Compose / PostgreSQL / Migration / API Server / WebUI Skeleton
  • authentik / Prometheus / Loki / Grafana
Gate：docker compose up → 全Service正常 → PostgreSQL migration成功 → Health Check PASS。
P2

AgentOS Core実装

Claude Code
  • Project / Phase / Gate / Task
  • Workflow Engine / Policy Engine / Approval / Audit
  • Artifact / API
  • Agentを本格稼働させなくてもProcess Controlが成立する状態を完成させる
P3

Core独立レビュー

Codex
  • Claude Code実装を修正前提ではなく、まず独立評価する
  • Architecture / Database Schema / API / RBAC / Policy / Approval / Audit / State Machine
  • Tests / Security / 要件定義→詳細設計→実装のTraceability
Gate-1：Critical=0、High=0、Tests PASS、Requirement Coverage OK。
P4

Agent Kernel実装

Claude Code
  • Intent Router / Planner / Agent Orchestrator / Task Scheduler
  • Model Router / Skill Registry / Tool Gateway / Runtime Interface
  • interface AgentRuntime を先に定義し、ClaudeRuntime / CodexRuntime / DeepSeekHarnessRuntimeを交換可能にする
P5

Agent Runtime検証

DeepSeek Harness
  • 主目的は新機能開発ではなく実行検証
  • Research / Developer / Reviewer / Knowledge Agent
  • Planning Loop / Tool Calls / Retry / Failure Recovery / Context維持 / Skill loading / Agent delegation / Long-running Task
  • Goal → 最大8 Round → Tool → Failure → Retry → Strategy Change → Complete
P6

Security・Test・Regression

Codex
  • Unit / Integration / Contract / E2E / Security / Regression / Recovery / Agent Evaluation
  • Policy迂回、ApprovalなしProduction、SecretのLog流出、Retry暴走を重点確認
Gate-2：Security bypassなし、必須Test PASS、Recovery成立、重大Runtime欠陥なし。
P7

外部Integration

Claude Code
  • Notion / Slack / Gmail / GitHub
  • authentik / Tailscale / Grafana
  • Slack → Request → AgentOS → PostgreSQL → Notion → GitHub の一貫性を維持
P8

Agent E2E・負荷・大量試験

DeepSeek Harness
  • 多数の擬似案件で Idea → Project → Plan → Agent → Code → Test → Review → Knowledge を反復
  • Agent成功率 / 平均Round / Retry率 / 失敗分類 / Token消費 / 処理時間 / Knowledge品質を測定
P9

Release Candidate Review

Codex
  • Release Auditorとしてコード以外も横断評価
  • Requirement / Architecture / Implementation / Tests / Security / Operations / Rollback / Monitoring
Gate-3：Critical=0、High=0、Release Blockerなし、Backup/Restore/Monitoring/Rollback成立。
P10

Production準備・文書整備

Claude Code
  • README / Runbook / Backup / Restore / Monitoring / Alert
  • Deployment / Rollback / Troubleshooting / Operations Playbook / Architecture Docs / ADR
  • Knowledge Baseとの整合を取る
Human Approvalまでで停止し、Production実行は人間承認後。
P11

運用・継続評価・自己改善

DeepSeek Harness
  • Agent Execution → Metrics → Failure → Experience → Improvement Candidate
  • Knowledge Discovery / Knowledge Quality Review / Knowledge Lifecycle
  • Skill Improvement / Prompt Evaluation / Regression
  • 改善案 → Test → Codex Review → Human Approval → Promotion
自動でProductionへ改善を昇格させない。
05

3製品の役割

Claude Code

「作る」

Builder / Architect
要件・設計・基盤・Core・Agent Kernel・Integration・Production準備。

Codex

「疑う・検証する」

Reviewer / Auditor
Core Review、Security/Test、Release Candidate Review。

DeepSeek Harness

「大量に動かす・試す」

Executor / Validator / Learner
長時間Loop、E2E、大量試験、継続評価、改善候補。

06

特に重要な運用ルール

同じフェーズ内で主担当AIを混ぜない。
P2をClaude Codeが実装中にCodexへ途中修正させない。P2完了後に成果物を固定してからCodexへ渡す。
P2 Claude Code 完了
        ↓
git commit / tag
phase/p2-core-complete
        ↓
P3 Codex Review
        ↓
git commit / tag
phase/p3-review-complete
        ↓
Gate-1
        ↓
P4へ
狙い：誰が何を作ったか、どのAIが何をレビューしたか、どのGateで承認されたかを明確にする。Mirai-AgentOSが重視するApproval/Audit思想を、開発プロセス自身にも適用する。
Builder ≠ Reviewer ≠ Executor
作るAI・疑うAI・大量実行するAIを分離する
