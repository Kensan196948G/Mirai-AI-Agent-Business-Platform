かんたん利用説明書
〜 はじめての人にもわかる AgentOS の使い方 〜

むずかしい言葉はできるだけ使いません。「困ったことを、ふだんの言葉で話すだけ」で AI が手伝ってくれる仕組みです。

1AgentOS ってなに？

5歳の子に説明するなら：「困ったことを話すと、賢いロボットのチームが調べて、作って、覚えてくれる会社の道具」です。ただし大事なことを決めるのは、いつも人間です。

Mirai AgentOS は、みらい建設工業のみんなが「こんな作業、もっとラクにならないかな」と思ったことを、AI に相談し、実際の仕組み（ツールやプログラム）に変えて、その学びを会社の知識として残すための基盤です。

あなたがやること困っていることを、ふだんの言葉で正しく説明する。大事な場面で「いいよ」「ダメ」を判断する。
AI がやること質問して整理する。調べる。作る。テストする。学んだことをまとめる。
AI がやらないこと本番への反映や大きな変更など、リスクの高いことを勝手に実行する。必ず人の承認を待ちます。
GitHub、PostgreSQL、AIモデルの種類…といった専門用語を知らなくても使えます。知らなくてよい部分は、この説明書でも省いています。

2画面の見かた

画面は大きく3つの部分に分かれています。

① 左のサイドメニュー行きたい画面を選びます。「概要」「基本操作」「運用・管理」「ヘルプ」に分かれています。見たい項目をクリックすると、右側にその説明だけが表示されます。赤い数字は「あなたの承認を待っている件数」です。
② 右上の操作エリアこの説明書ではライト／ダーク切替があります。実際のAgentOSでは検索、ロール（役割）、承認待ちなどの操作を配置します。
③ 真ん中の大きな場所選んだ画面の中身が表示されます。一覧をクリックすると右側に詳しい内容が出ます。

ライトモード / ダークモード

上のバーの ☀ Light / ☾ Dark ボタンを押すと、画面全体の色が切り替わります。目が疲れるときは暗い方がおすすめです。設定は次に開いたときも覚えています。

3まずやってみよう：AI相談

たとえ話：先生に「これ困ってるんだけど…」と話すと、先生が「いつ？どのくらい？」と聞いてくれて、最後に「じゃあこうしよう」と紙にまとめてくれる。それが AI相談です。
  1. 左メニューの AI相談（AI Consultation） を開きます。
  2. 下の入力欄に困っていることを書きます。例：「現場写真の整理に毎週3時間かかっている」。入力欄の上にある例文ボタンを押してもOKです。
  3. 送信 を押すか Enter キー。AI が 確認の質問 を返してきます（枚数は？保存先は？など）。
  4. 質問にざっくり答えて、もう一度送信します。正確でなくて大丈夫です。
  5. AI が IDEA 構造化 というカードを出します。「対象業務・現状・期待効果・必要データ・リスク・似た過去事例」が整理されています。
  6. 内容が良ければ 正式案件化（Project ID発番） を押します。DX-2026-00xx という番号がつき、案件一覧に登録されます。
相談を入力→AIが追加質問→Idea構造化→正式案件化（番号発番）→企画審査で承認

右側の「相談の流れ」に、いまどこまで進んだかが表示されます。新しい相談 で最初からやり直せます。

案件化しても、まだ何も作られません。次の「企画審査 Gate」で承認者（Approver）が「進めていいよ」と言ってから動き出します。

4案件を見る・進める

たとえ話：案件は「すごろく」。マスを順番に進み、大事なマス（GATE）では、止まって大人に「進んでいい？」と聞きます。

一覧の見かた

  • 上のボタン（すべて / Idea・審査 / 進行中 / 本番 / 保留・完了）で絞り込めます。
  • 行をクリックすると右側に詳細が開きます。
  • 上のバーの検索窓に番号や名前を入れて Enter でも探せます。

詳細パネルの読みかた

項目意味
Phase / Gate7つのマス。緑＝終わった、オレンジ＝いまここ、グレー＝まだ。GATE のマスは承認が必要です
KPI「どのくらい良くなったか」の目標と今の数字。棒が右まで伸びれば達成

次のマスに進める（State Transition）

詳細パネルの一番下に「次に進むボタン」があります（例：審査へ提出 R1、本番リリース R4）。

  • 白いボタン：そのまま進みます。
  • オレンジ色のボタン：承認が必要。押すと自動で「承認依頼」が作られ、承認画面に移動します。

案件を直接登録する

一覧右上の ＋ 案件を登録 から、案件名・概要・担当・リスク候補を入れて登録できます（AI相談を通さない方法）。

5承認のしかた（Approver・Reviewer向け）

たとえ話：ロボットが「外に遊びに行っていい？」と聞いてきます。危ないほど（R が大きいほど）、ちゃんと確認してから答えます。答えた理由はノートに残って、消せません。
  1. 左メニュー 承認（Approval）、または上の 🔔 を押します。
  2. 一覧から1件クリック。右側に「何を・なぜ・証拠（Evidence）・誰が承認済みか」が出ます。
  3. Evidence を読みます。テストの結果、セキュリティ検査、元に戻す手順（Rollback）などです。
  4. 下の 判断理由 の欄に、ひとことでも理由を書きます（必須）。
  5. ボタンを押します：承認（進めていい）/ 差戻し（直してもう一度）/ 却下（やめる）。

Approval Steps（承認の順番）

承認は順番に進みます。たとえば「Reviewer → Approver」。自分の番でないときや、自分のロールに権限がないときは、押しても Policy: DENY と表示されて実行されません（これも記録に残ります）。

承認すると何が起きる？

  • 企画審査 Gate を承認 → 案件が「承認済」になり、開発を始められます。
  • 本番リリースを承認 → 案件が「本番稼働」になり、止まっていた AI のタスク（Blocked）が動けるようになります。

6AI の仕事を見る：タスク・実行（Task / Agent Run）

たとえ話：ロボットの「日記」です。「どのロボットが、何を、どの頭脳（AIモデル）で、いくらかけて、何秒でやったか」が全部書いてあります。
見るところ意味
Agent担当ロボットの名前。調べる係（Research）、作る係（Developer）、チェックする係（Reviewer）など
Provider / Model使った AI の頭脳。作る係とチェックする係はわざと別の頭脳にしています（自分で自分を採点させないため）
Tokens / Cost / Latency読んだ量・書いた量 / かかったお金 / かかった時間
Tool Call · Policy Decisionロボットが使おうとした道具と、その可否。PERMIT＝OK、APPROVAL_REQUIRED＝人の承認待ち、DENY＝禁止
Trace「相談 → 計画 → タスク → 実行 → 成果物 → 承認」のつながり。どこから来た仕事かたどれます

ボタン

  • Retry / Resume：失敗したり止まった仕事をもう一度。ただし「入力データの形式が違う」系の失敗は、やり直しても直らないので押せません（理由が表示されます）。
  • Cancel：仕事を取り消します。終わったものは取り消せません。
  • 黄色い「Approval Pending」の帯：承認待ちで止まっています。クリックすると承認画面へ飛びます。

7ナレッジを育てる：ナレッジ候補（Knowledge）

たとえ話：ロボットが仕事のあとに「今日わかったこと」をメモしてきます。先生（Knowledge Curator）が読んで、「これはみんなの教科書に載せよう」か「これはボツ」を決めます。
  • カードには 種類（Lesson＝教訓 / ADR＝設計の決めごと / Playbook＝手順書 / Standard＝基準）と 品質スコア（80以上は緑、60未満は赤）が出ます。
  • 重複判定：すでに似た知識があれば「統合を推奨」と教えてくれます。
  • Notionへ昇格 を押すと、会社の知識ベース（Notion）に載ります。却下 はボツです。
Slack のおしゃべりの生ログは、そのままでは知識になりません（ルールで禁止）。整理された「学び」だけが昇格の対象です。

8監査・連携・監視（見るだけでOK）

監査ログ（Audit Log）

たとえ話：ページを破ったり書き換えたりできない「学級日誌」。前のページとつながる「合言葉（Hash）」があるので、こっそり書き換えるとすぐバレます。

種類やキーワードで絞り込めます。あなたの承認、AI の道具使用、ログイン、拒否された操作…全部ここにあります。管理者でも消せません。

外部連携（Integrations）

Notion（知識）、Slack（会話）、Gmail（メール）、GitHub（プログラム置き場）とのつながり具合。Connected なら正常、要確認 なら人のチェック待ちがあります。今すぐ同期 で最新にできます（開発者・管理者）。

Gmail は「契約・金額・機密・承認に関わるメール」には自動返信しません。必ず人が見ます。

監視（Observability）

AI が何回動いたか、いくら使ったか、どのくらい待っているか。上の 24時間 / 7日 / 30日 で期間を変えられます。費用が気になる人はここを見ましょう。

エージェント設定（Agent / Router）

どのロボットに、どの頭脳（AIモデル）を使わせるかの設定です。「作る係」と「チェックする係」が同じ系列の頭脳になると赤い警告が出ます。管理者・開発者以外は見るだけです。

9あなたの役割（ロール）

たとえ話：学校の「係」です。給食係は給食のことだけできます。係にない仕事をしようとすると「それは君の係じゃないよ」と止められます（それも日誌に書かれます）。

上のバーの選択肢でロールを切り替えると、できること・見えるメニューが変わります。

ロールだれ向けできること
Viewer全社員の基本見る、AI相談する
Developer作る人案件を作る・進める、AIタスクの再実行、連携の同期、エージェント設定
Reviewerチェックする人承認の「Reviewer」段階を担当、差戻し・却下
Approver決める人（部長など）Gate の最終承認、案件の状態を進める
Knowledge Curator知識を管理する人ナレッジ候補の昇格・却下
Administrator情シス全部。ユーザー・ロール管理も。ただし監査ログは消せない

10色とバッジの意味

リスク（R0〜R5）

R0 / R1 読むだけ・小さな変更　R2 中くらい　R3 人の承認が必要　R4 / R5 本番や外部に影響。慎重に

案件の状態

Idea → 審査中 → 承認済 → 開発中 → Staging / UAT → 本番稼働 → 完了　（横道：保留 / アーカイブ）

AIタスクの状態

実行中 動いている　レビュー チェック待ち　ブロック 承認待ちで止まっている　完了　失敗　取消

通知（右下に出る黒い箱）

操作の結果を数秒だけ表示します。オレンジ＝お知らせ、緑＝成功、黄＝注意、赤＝できませんでした。×で閉じられます。

11困ったときは

ボタンを押したら「Policy: DENY」と出た

あなたのロールにその操作の権限がありません。上のバーでロールを確認するか、Administrator に相談してください。試したこと自体は監査ログに残りますが、悪いことではありません。

承認ボタンが押せない / 反応しない

「判断理由」が空だと承認できません。ひとことでも書いてください。

Retry を押しても動かない

承認待ち（Blocked）か、やり直しても直らない種類の失敗です。画面の黄色または赤の帯に理由が書いてあります。

「ユーザー・ロール」メニューが見えない

Administrator だけに表示されます。

操作をやり直したい / 最初の状態に戻したい

操作内容はブラウザに保存されています。Administrator で「ユーザー・ロール」→ デモデータを初期化 を押すと最初の状態に戻ります。

AI相談で何を書けばいい？

「誰が・どのくらいの頻度で・何に困っていて・どうなったら嬉しいか」。この4つが入っていれば十分です。文章が下手でも AI が質問して補います。

最後にいちばん大事なこと：AI は手伝う係。決めるのはあなた。わからないときは、進めずに聞いてください。
