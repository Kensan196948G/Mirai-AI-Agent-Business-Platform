01

まず30秒で理解するAgentOS

AgentOSとは： 「AIに質問する道具」ではなく、目的を伝えると、必要な知識を調べ、計画を立て、複数のAI・Agent・Toolを使い分け、 必要なところだけ人間に承認を求め、結果を次回使える知識として残す仕組みです。
Before
AIへ個別に相談

相談、企画、設計、実装、記録が人ごと・ツールごとに分かれ、知識が散らばりやすい。

AgentOS
仕事の流れを統合

相談から開発・承認・運用までをAgentOSが一貫してつなぎ、状態をPostgreSQLで管理。

After
知識が次に再利用

成果や判断理由をNotionへ整理し、次の相談・企画・研究・開発で再利用する。

相談 → AI整理 → 人間レビュー → 実行 → 検証 → 知識化 → 次の改善

03

利用するIT・AIサービス

Knowledge

Notion

ADR、要件、研究、設計判断、Playbook、Lessons Learnedなど、長期的に残す知識の正本。

Collaboration

Slack

相談、議論、レビュー、Agent呼び出し、通知。生ログをそのまま知識にはしない。

Mail Gateway

Gmail

外部メール受付、自動返信、通知。契約・機密・承認事項は人間確認を必須化。

Engineering SoR

GitHub

Repository、Issue、PR、Test、Release、CI/CDなど開発履歴の正本。

Process SoR

PostgreSQL

案件、Phase、Gate、Task、Approval、Agent実行状態、監査ログ。Neonは使わずローカル運用。

Runtime

Docker

AgentOS API、WebUI、Worker、監視、認証などを分離して実行。

Identity

authentik

AgentOS独自のログイン、役割、権限管理。会社AD/Entra IDへ依存しない。

Private Access

Tailscale

AgentOS管理画面やサーバをインターネットへ直接公開せず、安全に接続。

Observability

Grafana

Agent、API、DB、AI利用量、障害状況を見える化するダッシュボード。

Metrics

Prometheus

CPU、Memory、API応答、Agent成功率など数値監視。

Logs

Loki / Alloy

Agent実行ログ、アプリログ、監査ログを収集・検索。

AI Layer

Claude / Codex / DeepSeek

調査、要件、設計、実装、テスト、レビューを役割分担して実行。

任意追加： n8nはGmail・Slack・外部Webhookなどの「連携自動化」には便利ですが、 AgentOS本体のWorkflow/Approvalをn8nへ依存させない設計を推奨します。
04

対象者別に見るAgentOS

👤

社内非エンジニアにとっては「AI付きの仕事受付窓口」

コードやAIモデルを意識せず、困りごと・改善案・依頼を自然な日本語で伝えることが中心です。

① 困りごとを伝える

「写真整理に時間がかかる」「報告書を自動化したい」など、普段の言葉で相談。

② AIが整理する

対象業務、頻度、時間、期待効果、必要データ、リスクを質問して整理。

③ 必要な時だけ確認

重要な判断・承認だけ人間が行い、細かな技術作業はAgent側へ任せる。

利用者に必要なのは「正しく問題を説明すること」。 GitHub、PostgreSQL、Docker、AIモデルの違いを理解する必要はありません。
📊

経営企画スタッフにとっては「DX案件ポートフォリオ＋意思決定支援基盤」

アイデアを案件化し、優先順位・効果・リスク・進捗・承認を横断管理することが主眼です。

案件化判断

Ideaを「価値・実現性・影響・リスク」で比較し、正式案件へ昇格。

Stage Gate

企画、要件、MVP、UAT、本番など節目ごとにGateを設け、承認履歴を保持。

KPI / ROI

工数削減、品質向上、利用率、AI採用率、コスト等をPostgreSQL/Grafanaで追跡。

経営企画にとって重要なのは「AIが何を言ったか」よりも、 どの案件を進めるか、どこで止めるか、何を承認したか、期待効果が出たかを説明できることです。
🏗️

建設土木技術者・研究者にとっては「専門知識を開発へ橋渡しする共同研究者」

技術知識・実務条件・基準・試験結果をAIが整理し、要件・設計・検証・知識化へつなげます。

専門条件を入力

施工条件、設計条件、判断基準、品質条件、例外、現場知見を自然言語で伝える。

AIと設計を詰める

Research、ADR、既存Knowledgeを参照し、仮説・設計案・検証項目を整理。

結果を再利用可能化

試験結果や失敗知見をNotionへ整理し、他案件・次回研究へ再利用。

技術判断の最終責任はAIへ移しません。 設計・施工・安全・品質に関する重要判断は、専門技術者が確認・承認する前提です。

01
相談受付 — AgentOS WebUIまたはSlackで困りごと・アイデア・研究テーマを入力。
02
課題明確化 — AIが追加質問し、対象、現状、頻度、期待効果、制約、データ、リスクを整理。
03
Idea構造化 — NotionへIdeaとして記録。類似案件や既存Knowledgeを参照。
04
正式案件化 — AgentOSがProject IDを発番し、PostgreSQLで案件・責任者・Phase・Gateを管理。
05
企画・審査 — 効果、費用、リスク、MVP範囲を整理。必要な人だけApproval Gateで承認。
06
要件・設計 — Claude等が要件・Architecture・ADR草案を作成し、専門家が確認。
07
開発案件化 — GitHub Repository / Issue / PRへつなぎ、AgentがTaskを分解。
08
MVP開発 — Claude Code / Codex / DeepSeekを使い分けて実装。
09
テスト — Unit / Integration / E2E / Security / Regression等を実施。
10
MVP評価 — 利用者・専門家が評価し、改善点と継続可否を判断。
11
Staging / UAT — 本番前に業務受入試験。重大不具合や運用条件を確認。
12
本番承認 — AgentOS Approval Gateでリリース条件、Rollback、監視、責任者承認を確認。
13
Production — 承認済ReleaseをGitHub CI/CD等からDeploy。
14
DevOps監視 — Grafana / Prometheus / Lokiで可用性、性能、Agent/AI利用量、障害を監視。
15
効果測定 — KPI、削減工数、品質、利用率、コスト、ROIを確認。
16
Knowledge化 — AIが成果・判断・失敗・教訓を整理し、人間レビュー後にNotionへ登録。

07

AIに任せすぎないための安全設計

Risk Level

読み取り、PR作成、本番Deploy、Secret変更、破壊的操作などをリスク別に分類。

Approval Gate

本番、権限、Security、重要技術判断などは人間の承認を必須化。

独立Review

実装したAgentとは別のAgent/モデルがレビューし、同じAIだけで自己完結させない。

例扱い
Knowledge検索、公開情報調査自動
コード作成、Branch/PR作成原則自動＋記録
Merge条件付き承認
本番Deploy人間承認必須
Secret / IAM / 権限変更人間承認必須
データ削除・破壊的操作強い承認＋Rollback確認
建設土木の重要技術判断専門技術者の確認・承認

導入は小さく始める

Step 1

基盤

Mirai-AgentOS、PostgreSQL、Docker、authentik、Tailscale。

Step 2

Knowledge

NotionのAI-CTO Knowledge Baseと連携。

Step 3

Agent / AI

Claude、Codex、DeepSeekをModel Routerで使い分け。

Step 4

業務接続

Slack、Gmail、GitHub、Approval、監視を追加。

最初から全社基盤として完成させる必要はありません。 まずは少人数で「1つのIdea → 1つのMVP → 1つのKnowledge化」を通し、 プロセスと承認設計が正しく回ることを確認してから拡張します。
