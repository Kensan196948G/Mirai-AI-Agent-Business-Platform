🛠️ 業務Agent の使い方（1 ページガイド）

Mirai AgentOS の「業務Agent（Agent Runs）」は、承認済みの公開資料を検索して比較や草案を 下書きとして 作る道具です。採用・施工可否・品質合否の判断はしません。最終判断は必ず人が行います。

😊 かんたんに言うと

「うちの技術で、この条件に合いそうなものを整理して」と頼むと、会社の公式サイトに載っている技術紹介・施工実績（承認済みのものだけ）を調べて、「確認できたこと」「まだ分からないこと」「根拠のページ」を並べた下書きを作ります。
出典に書かれていないことは「不明」と書きます。分からないことを勝手に埋めません。

🧭 使い方（4 ステップ）

1Agent を選ぶ
左メニュー「業務Agent（Agent Runs）」→ Agent を 1 つ選ぶ（下表）。
2相談内容を書く
例:「軟弱地盤の液状化対策として CPG工法 を適用できる条件と他の地盤改良技術との比較」。個人情報・位置情報・社外秘は書かない。
3Run を開始 → 待つ
通常 1〜2 分。状態が「完了」になったら成果物（草案）が表示されます。
4読んでレビューする
「確認できた事実」「不明点」「根拠」を確認し、問題なければ「レビュー済みにする」。気になる点はコメントに残す。

🔍 成果物の読み方

  • 確認できた事実: 出典（公式サイトの技術紹介・施工実績）に書かれていることだけ。各項目の根拠は下の「根拠」のリンク先で確認できます
  • 不明点・要確認: 出典に書かれていないこと。数値や条件を推測で補っていません。ここは人が調べる項目です
  • 仮定: 整理のために置いた前提。合っているか確認してください
  • 前回との差分: 同じ相談を再実行したときに、前回の草案と何が変わったか
  • レビュー済みにすると内容が固定され、以後は書き換えられません（改変があれば ⚠ が出ます）

🚦 安全のしくみ（知っておくと安心）

しくみ意味
承認済み出典だけを使う公開サイトの資料を DX推進部が承認したものだけが検索対象。未承認・隔離中の資料は使われません
人手確認が必須すべての草案は「要レビュー」で作られます。AI が自分で承認・昇格することはできません
正式承認は desknet's NEOアプリ内の「レビュー済み」「承認」は業務上の正式承認ではありません。Gate 承認は NEO Workflow で行います
費用の上限Run 1 件あたり約 $0.5、月全体で $5 の上限。超えると自動で止まります（1 件の実行は通常 $0.01 未満）
同時実行の上限1 人あたり同時 2 件、1 日 50 件まで。終わってから次を開始してください
記録誰が・いつ・何を実行し、どの出典を使ったかは監査ログに残ります

❓ 困ったとき

  • 「該当する承認済み出典が見つかりません」: 出典がまだ登録されていないか、言い方が違うかもしれません。技術名（例: MC-Caisson、CPG工法）や工事の種類（例: ケーソン据付、防波堤）を入れて再実行してみてください。それでも無ければ DX推進部へ「この資料を出典に追加してほしい」と依頼
  • 「失敗」になった: Run 詳細の「実行イベント」に理由が出ます。「LLM 出力を採用できず保留」は AI の出力が形式に合わなかったときで、再実行で直ることがあります。何度も失敗する場合は DX推進部へ
  • 「承認待ち」で止まっている: その Step は承認が必要な設定です。承認画面で Approver が判断します（自分の申請は自分で承認できません）
  • 個人情報を入れてしまった: すぐに DX推進部へ連絡してください。該当 Run と草案を削除します（削除は監査ログに残ります）
問い合わせ: DX推進部。詳しい仕様は `app/README.md`（開発者向け）、部署ごとの Agent／Skill の一覧と追加希望は「みらい建設工業_部署別Agent-Skill機能一覧.html」。
