Slack 設定手順書

Slackは、この基盤の「3名で気軽に話し合うおしゃべり部屋（案件チャンネル）」です。正式な承認はNEO Workflowで行いますが、その前の「相談・検討・レビュー」はここで行います。この基盤の議論に参加するのは3名のみです。

ELI5（やさしい説明）実行者：IT/DX/AIシステム開発者 参加：3名のみ目安：0.5〜1日

1

これは何？

たとえると：Slackは「打ち合わせ室」。案件ごとに部屋（チャンネル）を作り、3名がそこで意見を出し合います。部屋での「OK」はただの会話です。正式な「承認」は別の場所（NEO Workflow）で行います。検討中のメモはSlackの「Canvas（キャンバス＝共有メモ）」に書き、確定したらNotionへ移します。
言葉説明
チャンネル話題ごとの部屋。案件IDを名前に付けて分かりやすくする
Canvas（キャンバス）Slackの中で共同で書ける「共有メモ」。検討中のドラフトを書く場所
スレッド1つの話題に返信をまとめる機能。話が散らばらない
通知この基盤の「状態が変わったお知らせ」はdesknet's NEOが担当（Slackではない）
この基盤の鉄則：Slackでの「OK」「いいね」は正式な承認ではありません。承認・差戻しは必ず desknet's NEO Workflow で行い、その記録を正本とします。
2

だれがやるの？（参加者は3名のみ）

人役割
IT/DX/AIシステム開発者チャンネルを作成し、3名を招待する（管理者として設定）
社内経営企画担当者参加者：事業価値の視点で検討に加わる
社内建設土木技術者/研究者参加者：業務・技術の視点で検討に加わる
IT/DX/AIシステム開発者参加者：システム実現性の視点で検討に加わる
参加者は3名のみ：この基盤のSlackチャンネルには他の方を招待しません（経営企画担当者／建設土木技術者・研究者／IT・DX・AIシステム開発者の3名のみ）。将来、全社員へ広げる場合は運用ルールを見直します。

じゅんびするもの

  • 会社のSlackワークスペースが利用できる（なければ管理者に作成を依頼）
  • 3名のアカウントがSlackに登録されている
  • 案件チャンネルの名前のルール（命名規則）を決めておく
  • 全体計画書（ai-dx-dev-saas-setup-guide.html）の 3.6 を開いておく

やり方（手順）

1

チャンネルの名前のルールを3名で決める

案件チャンネルの名前は案件IDが分かる形にします。例：proj-2026-042-現場点検報告AI（＝案件ID DX-2026-0042 の案件チャンネル）。ルールを1つ決めて、今後すべて同じ形にします。

3名（決定）
2

基盤のチャンネルを作る

案件ごとの部屋を作る前に、基盤全体の連絡用チャンネル（例：ai-dx-platform）を1つ作り、3名を招待します。ここでは基盤の運用連絡や進め方の相談をします。

IT/DX/AIシステム開発者（作成・招待）
3

案件チャンネルの「ひな形ルール」を文書化する

チャンネルの最初のメッセージ（ピン留め）に、次の案内を書くルールにします：「この部屋は案件DX-2026-0042の検討室です。ここでのOKは正式承認ではありません。正式承認はNEO Workflowで行います。」

IT/DX/AIシステム開発者（文書化）→ 3名（確認）
4

Canvas（共有メモ）の使い方を決める

検討中のドラフト（例：アイデアの整理メモ）は、SlackのCanvasに書くことをルールにします。そして人間レビューが済んで「確定」になったらNotionへ移す、という流れを3名で共有します。

3名（合意）
5

テストで1件、検討の流れを通してみる

ためしに「現場点検報告書の自動作成」の話題をチャンネルで出し、Canvasにメモを書き、3名で意見を出し合う…という流れを試します。問題なければ完了です。

3名（テスト）
だいたいの目安：チャンネル作成とルール決めは0.5〜1日。テスト検討を含めると1〜2日ほど見ておくと安心です。
公式

Slack公式マニュアルに沿った実画面操作

この章の目的：「3名だけの検討室」という既存ルールを維持しつつ、Slackの現行公式ヘルプに沿って、チャンネル作成・招待・Canvas・スレッド・ピン留めまで実際に操作できる形にします。
現行Canvas仕様：Slackは2025年から旧来の「チャンネルCanvas / DM Canvas」を順次、チャンネル上部のCanvasタブへ移行しています。本手順書では現行方式である「Canvasをタブとして追加」を標準手順とします。
OFFICIAL STEP 1

3名だけの非公開チャンネルを作成する

  1. Slackデスクトップのサイドバーで ＋ をクリックします。
  2. Channel を選択します。
  3. 有料プランで選択肢が表示される場合は、通常のチャンネルなら Blank channel を選びます。
  4. チャンネル名を入力します。例：proj-2026-042-現場点検報告ai
  5. この基盤は参加者を3名に限定するため、Private / 非公開 を選択します。
  6. Create をクリックします。
公式の一般推奨との違い：Slackは通常「可能なら公開チャンネル」を推奨していますが、本基盤は既存方針として3名限定のため、案件検討チャンネルは非公開を採用します。
公式：Slack Help - Create a channel ／ What is a channel?
OFFICIAL STEP 2

3名をチャンネルへ追加する

  1. 作成したチャンネルを開きます。
  2. 右上のメンバーアイコンをクリックします。
  3. Add people を選択します。
  4. 経営企画担当者、建設土木技術者・研究者、IT/DX/AIシステム開発者の3名だけが登録されていることを確認します。
  5. 不足しているメンバーを名前またはメールアドレスで検索し、Add を実行します。
運用チェック：案件チャンネルに3名以外のユーザーが追加されていないことを、初期設定時と定期レビュー時に確認します。
公式：Slack Help - Add people to a channel
OFFICIAL STEP 3

チャンネル案内文を投稿し、ピン留めする

  1. 既存の「この部屋のルール」案内文をチャンネルへ投稿します。
  2. 投稿したメッセージにマウスを合わせます。
  3. ••• をクリックします。
  4. プランやUIに応じて Pin to channel、または Organise → Pin to channel を選びます。
  5. チャンネル上部の Pins タブから案内文を確認します。
ピン留め推奨内容：案件ID、参加者3名、正式承認はNEO Workflow、確定KnowledgeはNotion、機密情報の取扱いルール。
公式：Slack Help - Add and manage tabs
OFFICIAL STEP 4

検討用Canvasをチャンネルのタブとして追加する

  1. 対象チャンネルを開きます。
  2. 会話上部の ＋ をクリックします。
  3. Canvas を選択します。
  4. 既存Canvasを検索するか、新しいCanvasを作成します。
  5. Insert をクリックします。
  6. アクセス権を確認して Share をクリックします。
  7. Canvas名を DX-2026-0042 検討メモ のように案件ID付きにします。
Canvasの位置付け：Canvasは「検討中ドラフト」です。人間レビュー後に確定した内容だけNotionへ移す、という既存ルールはそのまま維持します。
公式：Slack Help - Use a canvas in Slack ／ Channel canvases feature change notice
OFFICIAL STEP 5

1つの話題はスレッドで議論する

  1. 返信したい元メッセージにマウスを合わせます。
  2. Reply in thread アイコンをクリックします。
  3. 返信を書いて送信します。
  4. 必要な場合だけ、返信をチャンネルのメイン表示にも送る設定を使用します。
  5. 案件の論点ごとにスレッドを分け、結論が出たらCanvasへ要点を整理します。
推奨：「MVP範囲」「Security」「KPI」「運用」など、論点ごとに親メッセージを1つ作ると後から追跡しやすくなります。
公式：Slack Help - Use threads to organize discussions
OFFICIAL STEP 6

Canvas・Pins・Messagesタブを運用の入口にする

Slackの現行UIでは、チャンネル上部にCanvas、Pins、Messages等のタブを配置できます。本基盤では次の使い分けを推奨します。

タブ本基盤での使い方
Messages3名の日常的な相談・議論。
Canvas検討中の構造化メモ、論点、未決定事項、次アクション。
Pinsチャンネルルール、案件ID、重要リンク、正式承認先の案内。
公式：Slack Help - Add and manage tabs
OFFICIAL STEP 7

テストで1案件の流れを通す

  1. テスト用案件チャンネルを非公開で作成します。
  2. 3名だけを追加します。
  3. ルール文を投稿してピン留めします。
  4. Canvasタブを作り、案件ID付きの検討メモを作成します。
  5. 1つの論点をスレッドで議論し、結論をCanvasへ整理します。
  6. 確定した内容だけをNotionへ転記し、正式承認が必要な事項はdesknet's NEO Workflowへ回します。
完了条件：Slackが「相談・検討」、Canvasが「ドラフト整理」、Notionが「確定Knowledge」、NEO Workflowが「正式承認」として混ざらず運用できること。

公式マニュアル参照先（2026-09-04確認）

  • Create a channel
  • Add people to a channel
  • Use a canvas in Slack
  • Feature change notice: Channel canvases
  • Use threads to organize discussions
  • Add and manage tabs in channels and DMs

サンプル（チャンネル名・案内文・Canvasの例）

ここでは、パイロット案件（例：現場写真・点検記録からの報告書自動作成 DX-2026-0042）を例に、Slackでの「チャンネルの作り方・使い方」の例を示します。

サンプル1：チャンネル名の例

チャンネル説明
ai-dx-platform基盤全体の連絡用（3名の運用連絡・進め方の相談）
proj-2026-042-現場点検報告AI案件 DX-2026-0042 の検討室（命名規則：proj-年度-連番-案件名）

サンプル2：チャンネルの案内文（ピン留めする文の例）

【この部屋のルール】
・対象案件：DX-2026-0042（現場写真・点検記録からの報告書自動作成）
・参加者：経営企画担当者／建設土木技術者・研究者／IT・DX・AIシステム開発者の3名のみ
・ここでの「OK」は正式承認ではありません。正式な承認・差戻しは desknet's NEO Workflow で行います。
・検討中のメモはCanvasに書き、確定した情報はNotionへ移します。

サンプル3：Canvas（検討メモ）の書き方の例

タイトル：DX-2026-0042 検討メモ（MVP範囲）
メモの内容：
・相談のきっかけ：点検写真と手書きメモからの報告書作成が大変（1件60分）
・話し合って分かったこと：対象は日常安全点検報告書が最初の候補
・決まったこと（仮）：MVPは「写真アップロード＋AI所見案＋帳票出力」
・未決定：人物マスキングの扱い／GPS利用範囲
・次アクション：KPI基準値の設定を経営企画担当者へ依頼

※Canvasは検討中のメモです。3名で「これで確定」となった内容だけをNotionへ移します。

6

できたか確かめる（完了チェック）

  • 基盤のチャンネルが作られ、3名だけが参加している（他の人はいない）
  • 案件チャンネルの命名規則が決まり、文書化された
  • チャンネルの案内文（「ここでのOKは正式承認ではない」）が用意された
  • Canvasの使い方（検討中ドラフト → 確定後Notion）が3名に共有された
  • テスト検討で、相談 → メモ整理 → 意見交換 の流れが動いた
7

ちゅういすること

  • 「OK」は承認じゃない：Slackで「OK」と言っても正式な承認になりません。承認が必要なときはNEO Workflowで申請を出します。
  • 参加者は3名のみ：案件チャンネルに3名以外を招待しない運用を守ります。
  • 生の会話をNotionにそのまま入れない：会話の結論はAIが整理 → 人間が確認 → Notionへ登録、の順番を守ります。
  • 会話が散らかったらスレッド：1つの話題はスレッドにまとめ、あとで「何が決まったか」を追いやすくします。
