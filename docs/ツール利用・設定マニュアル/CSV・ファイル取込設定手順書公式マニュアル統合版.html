共通の進め方と注意点（全ツール共通）

重要な前提：各製品のインポート機能は製品ごとに異なります。本手順書の「業務列（案件ID・Phase・Gate等）」はこの基盤の推奨設計、文字コード・取込方式・権限・更新動作は公式マニュアル準拠で記載します。契約プランやテナントUIで差が出る箇所だけ、管理画面／ログイン後Help Centerを最終確認してください。

0.1 インポートの進め方（共通の順番）

① CSVの内容を3名で確定する
   ↓
② テスト用に1件だけのCSVを作り、取込む（テスト環境 or 本番の小範囲）
   ↓
③ 表示・更新が正しいことを3名で確認する
   ↓
④ 本番データ（全件）を取込む
   ↓
⑤ 取込後にもう一度3名で確認し、レビュー記録に残す
なぜテストを先にやるのか：CSV取込は「一括で入る」反面、「間違った形式だと大量に失敗する」「気づかずに誤った値が入る」リスクがあります。必ず1件テスト → 確認 → 本番、の順で進めます。

0.2 共通の注意点

#注意点説明
1文字コード日本語を含むCSVは文字化けの原因になります。各ツールの指定（SJIS／UTF-8／BOMあり・なし）を確認してから保存する
21行目のタイトル行タイトル行（ヘッダー）の有無を取込時に正しく指定する（指定を間違えると、項目名がデータとして入る）
3重複・一意性案件ID・コード類は重複しないようにする。「更新」方式の場合、キー項目の指定を誤ると既存データを上書きする危険がある
4管理者権限インポート機能は管理者（または機能管理者）のみ利用できることが多い。実行ユーザーの権限を確認する
5取込前のバックアップ既存データを更新する前に、現状のデータをエクスポートして控えを取る
6エラーログの確認取込後に「成功件数・失敗件数・失敗理由」を必ず確認する（失敗行だけ直して再取込）
7取込後は手作業の置き換えではないCSV取込後も、各ツールの権限設定・承認者設定など「CSVでは入らない設定」を画面で行う必要がある

0.3 取込前の「公式仕様確認」

  • 画面名は現在の製品UIを優先：特にSaaS（Notion、Lightblue、Slack）は継続的にUIが変わります。
  • 既存データ更新か追加かを先に確認：Notion CSVは基本的に「追加」であり、既存行を更新しません。
  • キー照合の有無を確認：AppSuiteのappsimportで変更・削除を行う場合は-key_field_nameが必要です。
  • NEOのユーザー／組織はNEO本体で管理：AppSuite内の「社員マスタ」「部署マスタ」は業務用アプリデータとして別物です。
  • ファイル取込制限：desknet's NEO側で「添付ファイル使用設定」が禁止されている場合、CSVインポート／エクスポートにも影響します。

1.A 現行AppSuite公式仕様

  • 公式確認済み既存アプリの「その他の機能」からExcel/CSVファイルをインポートできます。
  • 公式確認済みアプリ作成時にもExcel/CSVファイルからアプリケーション作成＋データ一括登録ができます。
  • 公式確認済み入力ファイルは、Excelワークシート（.xlsx、5MB未満）またはカンマ／タブ区切りのCSVを利用できます。
  • 公式確認済み画面操作には対象アプリのインポート操作に必要なアクセス権が必要です。
  • 公式確認済みappsimportはCSV専用で、クラウド環境でも利用可能です。CLI実行ユーザーは対象アプリの管理権限が必要です。

1.3 インポートの手順

画面で取り込む場合

  • AppSuiteの対象アプリを開き、「その他の機能」→「Excel/CSVファイルからインポート」を選ぶ
  • ExcelまたはCSVファイルを選択する。CSVの場合は文字コード・区切り文字を確認する
  • 対象（アプリ本体／表部品）と実行する処理を選び、[次へ]へ進む
  • 2画面目で、ファイル列とAppSuite部品の対応を確認する。先頭行をヘッダー扱いする場合はタイトル行を除外する
  • まず1件だけで実行し、登録／変更結果を確認してから全件を投入する

コマンドラインツールで取り込む場合（大量・定期用）

  • 公式のAppSuiteコマンドラインツールを利用する
  • 公式例に合わせ、-l（ログ）、-delimiter、-title_except、更新時の-key_field_nameを明示する
  • アクセスキーは個人設定 → アクセスキー設定で発行し、アプリケーション識別子はアプリケーション設定 → オプション機能 → API設定で確認する
    • "C:\Program Files\desknet's NEO\bin\appsimport.exe" ^ -conf "C:\tmp\conf.txt" ^ -access_key sampleAccessKey ^ -app_alias sample ^ -f "C:\tmp\import.csv" ^ -l "C:\tmp\import.log" ^ -char_code utf8 ^ -delimiter comma ^ -title_except on ^ -import_type update ^ -match_with_title on ^ -key_field_name "案件ID" ^ -exec_user login ^ -error_stop on

    ※上記はこの基盤向けの例です。案件IDで既存データを変更する場合、案件ID部品は重複禁止など、一意に照合できる設計にしてください。

  • 失敗行はログファイルに出力されるので確認する
注意点（AppSuite）：
  • 画面インポートは対象操作のアクセス権が必要。appsimport実行は対象アプリの管理権限が必要
  • 文字コードは SJIS（日本語のみ）またはUTF-8 を指定（UTF-8はBOMあり/なしの区別あり）
  • 参照マスタ（部署・社員・Phase等）を先に入れること（後から入れると参照エラー）
  • 案件IDを自動生成する設計の場合は、CSV側で無理に値を入れない。既存行更新に案件IDを使う場合は、逆に照合キーとして一意性を保証する
  • 取込後、ダッシュボード・権限・承認者設定などCSVで入らない項目を画面で仕上げる

desknet's NEO Workflow（承認フロー）のファイル取込

設定担当：DX推進部担当者（確認：3名）。申請書の「書式」は公式のファイルインポート／エクスポートに対応。申請経路は公式画面で作成。

2.0 先にNEO本体のユーザー／組織を整える

Workflowの承認者はdesknet's NEOのユーザーを使用します。承認経路を作る前に、NEO本体のユーザー・組織情報を正しく登録してください。

システム管理 → 運用設定 → ユーザー設定 → ユーザー情報のインポート
システム管理 → 運用設定 → 組織設定 → 組織情報のインポート
  • どちらもファイルから一括登録・変更が可能。
  • インポート画面で登録項目の順番をファイルに合わせて並べ替え可能。
  • 先頭行を無視する設定、文字コード、区切り文字を指定可能。
  • 既存情報を変更する場合は、先にエクスポートして控えを取得する。

2.1 インポートの順番

① 申請書カテゴリーを画面で作成（例：DX案件）
   ↓
② 申請経路を画面で作成（承認者：3名＋上位Gate Owner）※CSV不可
   ↓
③ 申請書の「書式」をファイルで取り込む（Gate 1用）※ファイル取込対応
   ↓
④ 表題・書式・経路をまとめた「申請書」として完成させる
   ↓
⑤ Gate 2〜5は、①の申請書を複製 or 書式をエクスポート→調整→インポートで作る
なぜ②（経路）が先か：申請書を完成させるには経路が必要です。承認者（3名）がAppSuiteマスタやNEOのユーザーに登録済みであることを先に確認します。

※重要：上の表は業務設計の概念であり、NEO公式の実ファイル列仕様そのものではありません。安全な方法は、まず画面でGate 1の書式を1本作る → 公式の「書式のエクスポート」で雛形を取得 → その形式を基準にすることです。
注意点（NEO Workflow）：
  • 公式マニュアルでは、申請経路は「申請書管理 → 申請経路設定」で作成する手順が案内されています。書式のようなファイルインポート機能は案内されていないため、承認者（3名＋上位Gate Owner）は画面設定を正とします
  • AppSuiteアプリと連携している申請書はエクスポート不可（取込む書式が連携申請書でないことを確認）
  • 書式を取り込んだ直後は管理組織が空なので、後から設定する
  • 申請書の表内部品（明細行の初期値など）はCSVで複写できる（参考記事）
  • 5つのGateは「1本完成させてから複製し、承認者だけ差し替える」のが速い

2.3 公式の書式インポート／エクスポート手順

設定メニュー → 申請書管理 → 書式のインポート
  1. 申請書名を入力。
  2. ファイルを選択。
  3. [設定を変更]で文字コードと区切り文字を指定。
  4. [インポート]を実行。
  5. インポート後、管理組織が空になるため管理組織を設定。
設定メニュー → 申請書管理 → 書式のエクスポート
  • 申請書を選択して書式をエクスポートできる。
  • AppSuiteのアプリケーションと連携している申請書はエクスポート不可。
  • このメニューの表示には、システム管理者／対象範囲「すべて」の機能管理者／申請書・経路管理者等の条件がある。

3.3 インポートの手順（Notion標準のCSVインポート）

  • Notionで設定 → インポート → CSVを開く。またはページ内で/csvと入力する
  • CSVファイルをアップロードし、新しいデータベースを作るか、既存データベースへ取り込むかを選ぶ

注意点（Notion）：

  • 読み込み後は、Status等の列を「セレクト（選択肢）」型に変更して選択肢を定義する
  • 人間レビュー前の生情報（Slackログ等）は入れない。Notionに入れるのは確定Knowledgeのみ
  • アクセス権は3名＋案件関係者に制限し、全社公開は運用拡大時に行う

3.4 Notion公式CSV仕様で必ず押さえる点

  • 公式確認済みCSVの行 → データベースアイテム（ページ）、列 → プロパティとして取り込まれる。
  • 公式確認済みCSVは新規DBだけでなく、既存DBにも列マッピングして追加できる。
  • 重要CSV取込／マージは既存行を更新しない。新しい行を追加する。案件IDが同じでも自動更新にはならない。
  • 公式確認済み文字化け時はUTF-8で再エクスポート。
  • 公式確認済み無料プランは1ファイル5MB、有料プランは50MB。
  • 公式確認済み新規CSVインポートでは新しいRelation／Rollup／Formulaを作成できないため、取込後にNotion側で構築する。
  • 公式確認済み日付の推奨取込形式はMM/DD/YYYY。
重複対策：既存DBへの再取込前にIdea ID／案件IDで重複チェックし、同じ行を再投入しない運用にしてください。
4

Lightblue（AI窓口）のナレッジ取り込み

設定担当：IT/DX/AIシステム開発者（確認：3名）。Lightblue（＝Lightblue Assistant）では、AIが回答に使う社内ナレッジ（RAG用データ）を取り込む。CSVというよりファイル（PDF/Word/Excel/PPT）のアップロードと、Notion等ストレージ連携が中心。

4.1 取り込みの順番

① 参照元を3名で決める（どのKnowledgeをAIに読ませるか）
   ↓
② 参照元を準備する（Notionのページ/DB or ファイル化）
   ↓
③ Lightblueで「独自データ連携」を設定（ファイルUP or Notion連携 or ストレージ連携）
   ↓
④ 「マイアシスタント」を作成（プロンプト自動生成）※画面操作
   ↓
⑤ テスト質問で回答精度を確認し、必要なら参照範囲・プロンプトを調整

4.2 準備するファイル・連携先（案）

取り込むもの手段例
Idea DB・教訓・決定事項Notion連携（公式対応）人間レビュー済みの確定Knowledgeだけを参照範囲にする
企画書・基準書・帳票様式ファイルアップロードPDF／Word／Excel／PPT
その他の社内文書ストレージ連携Google Drive／Box 等（契約プランによる）
注意点（Lightblue）：
  • 参照させる範囲は3名で決める（社外秘・個人情報を含むNotionページをAIに読ませない）
  • 人間レビュー前の生情報（Slackの生ログ等）は参照させない
  • 「マイアシスタント」は、作成したいアシスタントの特徴を入力してプロンプトを自動生成できることが公式に案内されています。CSVによるアシスタント定義の一括登録可否は公開公式資料では確認できないため、現テナントのHelp Centerを確認します
  • Notion連携自体は公式提供済みです。現在契約中プランの容量・ユーザー数・管理権限・最新UIはログイン後Help Center／契約条件で最終確認します
  • AIの回答は「案」。最終的な確定は人間（3名）が行う

Slack（参考：CSV/Textインポートは「移行用」）

元版ではSlackを対象外としていましたが、公式ヘルプ上はCSV/Textファイルからメッセージ・チャンネル・ユーザーアカウントを移行するインポート機能があります。 ただし、これは通常の3名ワークスペース初期設定ではなく、別システム／別ワークスペースからの移行用途です。

5.1 公式CSV/Textインポート

Admin → Workspace settings → Security → Import & export data → Import → CSV/Text File

公式CSV/Text形式では、メッセージを1行ずつ並べ、列順は次の形式です。

timestamp, channel, username, text
  • メッセージはタイムスタンプの古い順に並べる。
  • ユーザーとチャンネルを既存Slackへマッピングしてからインポートを確定する。
  • 新規ユーザーとして招待する場合はメールアドレスが必要。
  • このインポートはWorkspace Owner向けの移行機能として扱う。
この基盤での結論：初期3名の参加者設定にはCSV/Textインポートを使いません。 3名は通常の招待／管理画面で追加し、将来Slack移行が発生した場合だけ本機能を利用します。

実行チェックリスト（取込前・取込後）

取込前（共通）

  • 3名でCSVの内容（マスタ値・項目）を確認した
  • 文字コード（SJIS/UTF-8）と区切り文字を確認した
  • 1行目のタイトル行の有無を確認した
  • 参照元マスタを先に入れる順番になっている（AppSuite）
  • NEO本体ユーザー／組織とAppSuite業務マスタを混同していない
  • Notion既存DBへ再取込する場合、案件ID／Idea IDの重複確認をした
  • 既存データ更新の前にエクスポート（バックアップ）を取った
  • 実行ユーザーに管理者権限がある

取込後（共通）

  • 成功件数・失敗件数を確認した（失敗行はログで確認）
  • テストデータ（1件）を登録し、表示を3名で確認した
  • CSVで入らない設定（権限・承認者・ダッシュボード等）を画面で仕上げた
  • レビュー記録に結果を記載した
