## 0. 共通の進め方と注意点（全ツール共通）

### 0.1 インポートの進め方（共通の順番）

1. **CSVの内容を3名で確定する**（どのマスタ値・どの項目を入れるか）
2. **テスト用に1件だけのCSVを作り、テスト環境（または本番の小範囲）で取込む**
3. **表示・更新が正しいことを3名で確認する**
4. **本番データ（全件）を取込む**
5. **取込後にもう一度3名で確認し、レビュー記録に残す**

> **なぜテストを先にやるのか：** CSV取込は「一括で入る」反面、「間違った形式だと大量に失敗する」「気づかずに誤った値が入る」リスクがあります。必ず1件テスト → 確認 → 本番、の順で進めます。

### 0.2 共通の注意点

| # | 注意点 | 説明 |
|---|---|---|
| 1 | **文字コード** | 日本語を含むCSVは文字化けの原因になります。各ツールの指定（SJIS／UTF-8／BOMあり・なし）を確認してから保存する |
| 2 | **1行目のタイトル行** | タイトル行（ヘッダー）の有無を取込時に正しく指定する（「1行目は項目名」の指定を間違えると、項目名がデータとして入る） |
| 3 | **重複・一意性** | 案件ID・コード類は重複しないようにする。取込方式が「更新」の場合、キー項目の指定を誤ると既存データを上書きする危険がある |
| 4 | **管理者権限** | インポート機能は管理者（または機能管理者）のみ利用できることが多い。実行ユーザーの権限を確認する |
| 5 | **取込前のバックアップ** | 既存データを更新する前に、現状のデータをエクスポートして控えを取る |
| 6 | **エラーログの確認** | 取込後に「成功件数・失敗件数・失敗理由」を必ず確認する（失敗行だけ直して再取込） |
| 7 | **取込後は手作業の置き換えではない** | CSV取込後も、各ツールの権限設定・承認者設定など「CSVでは入らない設定」を画面で行う必要がある |

## 1. AppSuite（案件台帳・マスタ）のCSVインポート

### 1.1 担当と対象

- **設定担当：DX推進部担当者**（確認：3名）
- この基盤では、**案件ID採番ルール・部署・社員・Phase・Gate・Statusの各マスタ**と、**案件台帳の初期データ**をCSVで入れることを想定する
- インポート手段は2つ：**画面の「CSVファイルからインポート」** と **コマンドラインツール（appsimport）**

### 1.2 インポートの順番

```text
① 部署マスタ
   ↓
② 社員マスタ（3名＋承認者）
   ↓
③ Phaseマスタ / Gateマスタ / Statusマスタ
   ↓
④ 案件ID採番ルールの設定（または採番方法の決定）
   ↓
⑤ 案件台帳アプリの設計（項目定義）…テンプレートのファイル取込 or 画面で作成
   ↓
⑥ 案件台帳の初期データ（既存案件がある場合のみ）
```

> **順番の理由：** 案件台帳に「部署」「社員」「Phase」などを参照する項目がある場合、**先に参照元（マスタ）を入れておかないとエラー**になります。参照関係のあるマスタを先に取り込みます。

### 1.3 CSVの列構成（案）※各マスタ

#### ① 部署マスタ

| 列名（案） | 内容 | 例 | 必須 |
|---|---|---|---|
| 部署コード | 一意なコード | `D001` | ○ |
| 部署名 | 表示名 | 経営企画部 | ○ |
| 上位部署コード | 階層がある場合の親 | （空欄） | △ |

#### ② 社員マスタ

| 列名（案） | 内容 | 例 | 必須 |
|---|---|---|---|
| 社員ID | ログインID等 | `keiei01` | ○ |
| 氏名 | 氏名 | （例）経営企画担当者 | ○ |
| 所属部署コード | ①の部署コード | `D001` | ○ |
| 役割 | この基盤での役割 | `経営企画担当者`／`建設土木技術者・研究者`／`IT・DX・AI開発者` | ○ |
| メールアドレス | 通知用 | （例）xxx@example.com | △ |

#### ③ Phaseマスタ

| 列名（案） | 内容 | 例 |
|---|---|---|
| Phaseコード | コード | `Idea`／`Planning`／`Definition`／`MVP`／`Staging`／`Production`／`Operation` |
| Phase名 | 表示名 | アイデア／企画／要件定義／MVP／本番準備／本番／運用 |
| 表示順 | 並び順 | 1〜7 |

#### ④ Gateマスタ

| 列名（案） | 内容 | 例 |
|---|---|---|
| Gateコード | コード | `Gate1`〜`Gate5` |
| Gate名 | 表示名 | 企画承認／開発承認／MVP承認／本番移行承認／Release承認 |
| 主承認者（役割） | 承認者（参考情報） | 経営企画担当者 等 |
| 表示順 | 並び順 | 1〜5 |

#### ⑤ Statusマスタ

| 列名（案） | 内容 | 例 |
|---|---|---|
| Statusコード | コード | `APPLY`／`APPROVED`／`RETURNED`／`DONE`／`STOP` |
| Status名 | 表示名 | 申請中／承認／差戻し／完了／停止 |

#### ⑥ 案件台帳の初期データ（既存案件がある場合）

| 列名（案） | 内容 | 例 |
|---|---|---|
| 案件ID | 共通キー | `DX-2026-0042` |
| 案件名 | 案件名 | 現場写真・点検記録からの報告書自動作成 |
| 提案者（社員ID） | ②の社員ID | （例）現場監督のID |
| Phaseコード | ③のコード | `MVP` |
| Gate状態 | ④のコード | `Gate3` |
| KPI目標 | 効果測定指標 | 作成時間 60分→20分 |

### 1.4 インポートの手順

**画面で取り込む場合**
1. AppSuiteの対象アプリを開き「その他の機能＞CSVファイルからインポート」を選ぶ
2. インポート画面の「使い方」で、列名・形式（新規/更新）を確認する
3. CSVファイルを選択し、文字コード・区切り文字（カンマ/タブ）・1行目タイトル有無を指定する
4. プレビューで正しく読めたか確認してから実行する
5. 結果（成功・失敗件数）を確認する

**コマンドラインツールで取り込む場合（大量・定期用）**
- 公式の[AppSuiteコマンドラインツール](https://www.desknets.com/neo/download/ascmdtool.html)を利用する
- 実行例（Windows）：
  `appsimport.exe -conf 接続設定ファイル -access_key アクセスキー -app_alias アプリ識別子 -f import.csv -char_code sjis -import_type update`
- アクセスキー・アプリ識別子は、対象アプリの「アプリケーション設定＞詳細＞API設定」で確認する
- 失敗行はログファイルに出力されるので確認する

### 1.5 注意点（AppSuite）

- インポートを実行するユーザーに**そのアプリの管理権限**が必要
- 文字コードは **SJIS（日本語のみ）またはUTF-8** を指定する（UTF-8はBOMあり/なしの区別あり）
- **参照マスタ（部署・社員・Phase等）を先に入れる**こと（後から入れると参照エラーになる）
- 案件IDの採番が「自動付番」の場合、案件ID列は入れずに空欄にする（重複採番を防ぐ）
- 取り込んだ後、**ダッシュボード・権限・承認者設定などCSVで入らない項目**を画面で仕上げる

## 2. desknet's NEO Workflow（承認フロー）のファイル取込

### 2.1 担当と対象

- **設定担当：DX推進部担当者**（確認：3名）
- NEO Workflowでは、**申請書の「書式」（フォームの項目構成）をファイルで取り込める**（申請書管理の「書式のインポート/エクスポート」）
- **申請経路（承認の順番・承認者）はCSVでは入らない** → 画面で作成・複製する

### 2.2 インポートの順番

```text
① 申請書カテゴリーを画面で作成（例：DX案件）
   ↓
② 申請経路を画面で作成（承認者：3名＋上位Gate Owner）※CSV不可
   ↓
③ 申請書の「書式」をファイルで取り込む（Gate 1用）※CSV対応
   ↓
④ 表題・書式・経路をまとめた「申請書」として完成させる
   ↓
⑤ Gate 2〜5は、①の申請書を複製 or 書式をエクスポート→調整→インポートで作る
```

> **なぜ②（経路）が先か：** 申請書を完成させるには経路が必要です。承認者（3名）がAppSuiteマスタやNEOのユーザーに登録済みであることを先に確認します。

### 2.3 書式インポート用ファイルの列構成（案）

NEOの申請書「書式」のファイル形式は、**取込画面で文字コード・区切り文字を指定するCSV系の形式**です。項目の並びは製品の「使い方」に従う必要がありますが、概念的な列構成は以下のとおりです（※要ベンダー確認）。

| 列（概念） | 内容 | 例 |
|---|---|---|
| 項目名 | フォームに表示する項目名 | 案件ID／申請者／対象現場／添付写真 |
| 部品種別 | 入力部品の種類 | テキスト／プルダウン／表部品／添付ファイル |
| 必須/任意 | 入力必須か | 必須／任意 |
| 選択肢（プルダウン等） | 選択肢の列挙 | Gate1, Gate2, … |
| 表示順 | フォーム上の並び順 | 1〜 |

> **※重要：** 実際の取込ファイルの列仕様は、NEOの管理画面「申請書管理＞書式のインポート」の**「使い方」表示を確認してから作成してください**。本手順書はあくまで概念案です。

### 2.4 注意点（NEO Workflow）

- **申請経路はCSVでは取り込めません**。承認者（3名＋上位Gate Owner）の設定は画面で行います
- **AppSuiteアプリと連携している申請書はエクスポート不可**（取込む書式が連携申請書でないことを確認する）
- 書式を取り込んだ直後は**管理組織が空**なので、後から設定する
- 申請書の**表内部品（明細行の初期値など）はCSVで複写**できる（[参考記事](https://www.desknets.com/neo/users/media/desknets/11359/)）
- 5つのGateは「1本完成させてから複製し、承認者だけ差し替える」のが速い

## 3. Notion（Knowledge基盤）のCSVインポート

### 3.1 担当と対象

- **設定担当：IT/DX/AIシステム開発者**（確認：3名）
- この基盤では、**Idea DB（アイデア台帳）** をCSVで作成する。Decision Log・教訓台帳も同様の手順で作れる

### 3.2 インポートの順番

```text
① Idea DBのCSVを用意する（1行目＝項目名、2行目以降＝データ）
   ↓
② Notionで「CSVインポート」を選び、CSVを読み込む
   ↓
③ プロパティ（列）の型を整える（テキスト/セレクト/日付/担当者など）
   ↓
④ 必要に応じて「データベース」として作り直す or 既存DBに移す
   ↓
⑤ 企画書・要件定義書などは「ページテンプレート」として別途作成
```

### 3.3 Idea DB用CSVの列構成（案）※14項目

| 列名（CSVヘッダー） | 内容 | 入力例 |
|---|---|---|
| Idea ID | アイデア識別子 | `IDEA-2026-0001` |
| 提案者 | 発案者 | （例）現場監督 |
| 所属 | 部署 | 建設土木技術部 |
| 原課題 | 最初の困りごと | 点検写真と手書きメモからの報告書作成が大変 |
| 壁打ち結果 | AI整理の結果 | 写真整理・転記・帳票作成に1件60分 |
| 目的 | 解決したいこと | 報告書作成時間の削減 |
| 対象者 | 利用者 | 現場監督・施工管理者 |
| 期待効果 | 工数・品質等 | 60分→20分 |
| MVP | 最小実装範囲 | 写真UP・AI所見案・帳票出力 |
| 概算工数 | PoC/MVP | PoC 2〜4週間 |
| リスク | 情報・技術等 | 写真に人物・位置情報（要マスキング） |
| 類似案件 | 過去案件 | （該当なし） |
| 関連Knowledge | Notionページ | （後でリンク） |
| Status | 状態 | `企画候補` |

### 3.4 インポートの手順（Notion標準のCSVインポート）

1. Notionで新規ページを作成し、「CSVインポート」を選択する（[参考](https://info.nextmode.co.jp/blog/notion-import-csv-file)）
2. CSVファイルを選ぶと、**1行目がプロパティ（列）名**として読み込まれる
3. 読み込まれた表の列の型を調整する（Status→セレクト、Idea ID→テキスト、日付列→日付 等）
4. 必要に応じて「…」メニューから**データベース化**する
5. 以後の運用で使う**ビュー（テーブル/カンバン）**を整える

> **大量レコードの追加（API）**：既存のデータベースへ後から大量追加する場合は、Notion APIや連携ツールで一括投入も可能です（[導入メモ](https://zenn.dev/ttskch/articles/9bc88a0d468604)）。まずはCSVインポートで形を作るのが簡単です。

### 3.5 注意点（Notion）

- CSVの**1行目がそのままプロパティ名**になる。列名は最初から分かりやすい名前にする（後から変更も可）
- 読み込み後は、**Status等の列を「セレクト（選択肢）」型**に変更して選択肢を定義する
- **人間レビュー前の生情報（Slackログ等）は入れない**。Notionに入れるのは確定Knowledgeのみ
- アクセス権は3名＋案件関係者に制限し、全社公開は運用拡大時に行う

## 4. Lightblue（AI窓口）のナレッジ取り込み

### 4.1 担当と対象

- **設定担当：IT/DX/AIシステム開発者**（確認：3名）
- Lightblue（＝Lightblue Assistant）では、**AIが回答に使う社内ナレッジ（RAG用データ）を取り込む**。CSVというより**ファイル（PDF/Word/Excel/PPT）のアップロードと、Notion等ストレージとの連携**が中心

### 4.2 取り込みの順番

```text
① 参照元を3名で決める（どのKnowledgeをAIに読ませるか）
   ↓
② 参照元を準備する（Notionのページ/DB or ファイル化）
   ↓
③ Lightblueで「独自データ連携」を設定（ファイルUP or Notion連携 or ストレージ連携）
   ↓
④ 「マイアシスタント」を作成（プロンプト自動生成）※画面操作
   ↓
⑤ テスト質問で回答精度を確認し、必要なら参照範囲・プロンプトを調整
```

### 4.3 準備するファイル・連携先（案）

| 取り込むもの | 手段 | 例 |
|---|---|---|
| Idea DB・教訓・決定事項 | **Notion連携**（公式対応） | 人間レビュー済みの確定Knowledgeだけを参照範囲にする |
| 企画書・基準書・帳票様式 | **ファイルアップロード** | PDF／Word／Excel／PPT |
| その他の社内文書 | ストレージ連携 | Google Drive／Box 等（契約プランによる） |

### 4.4 注意点（Lightblue）

- **参照させる範囲は3名で決める**（社外秘・個人情報を含むNotionページをAIに読ませない）
- **人間レビュー前の生情報（Slackの生ログ等）は参照させない**
- 「マイアシスタント」のプロンプトは**管理画面上で特徴を入力して自動生成**する方式（ユーザー側からのCSV一括定義は現状不可。※要ベンダー確認）
- **契約プランで使える機能（Notion連携・容量・ユーザー数）はベンダーに確認する（Q6）**。ビジネスプランでどこまで対応するかが論点
- AIの回答は「案」。**最終的な確定は人間（3名）が行う**のは他のツールと同じ

## 付録A：実行チェックリスト（取込前・取込後）

### 取込前（共通）

- [ ] 3名でCSVの内容（マスタ値・項目）を確認した
- [ ] 文字コード（SJIS/UTF-8）と区切り文字を確認した
- [ ] 1行目のタイトル行の有無を確認した
- [ ] 参照元マスタを先に入れる順番になっている（AppSuite）
- [ ] 既存データ更新の前にエクスポート（バックアップ）を取った
- [ ] 実行ユーザーに管理者権限がある

### 取込後（共通）

- [ ] 成功件数・失敗件数を確認した（失敗行はログで確認）
- [ ] テストデータ（1件）を登録し、表示を3名で確認した
- [ ] CSVで入らない設定（権限・承認者・ダッシュボード等）を画面で仕上げた
- [ ] レビュー記録に結果を記載した

### ツール別

| ツール | 取込後の追加確認 |
|---|---|
| AppSuite | 案件ID採番が重複しないか／案件台帳からマスタ参照が正しく表示されるか |
| NEO Workflow | 申請書を1回テスト申請し、経路どおり承認が回るか |
| Notion | プロパティ型（セレクト等）が正しいか／アクセス権が3名限定か |
| Lightblue | テスト質問でNotionのKnowledgeを正しく参照するか／範囲外の情報を回答しないか |
