経営・レビュー者向けサマリ

1枚で読む
何を作るか：全社員のアイデアを「アイデア → 企画 → 承認 → 開発 → 本番 → 効果測定 → ナレッジ」のルールで回し、3名（経営企画／建設土木技術・研究／IT・DX・AI開発＝3 Authorityの担い手）が審査・承認・運用するための業務基盤（仕組みと設定）。コードは書かず、会社で契約済みのSaaSを組み合わせて設定する。Slack上での議論は3名のみで行う（他の方は含めない）。

4

API / Webhook 連携の要否（自前アプリ不要の判定）

判定の結論：基盤（案件管理フロー）の初期構築では、自前アプリ（外部受信サーバ・コード開発）は不要。 ※監視基盤（自前Web構築予定）は別途論点（4.4節）。

4.1 判定の考え方

本基盤の設計原則は 「承認・確定は必ず人間」（Human-in-the-Loop）です。このため：

自動化してよい通知（誰が次に何をするか）、状態の転記・同期、定型変換、AIによる下書き生成
自動化しないGate承認・差戻し判定・Knowledge化の最終確認（必ず人間）

4.2 連携パターン別の要否（基盤＝案件管理フロー）

連携したいこと手段自前アプリ（受信サーバ）は必要か備考
① 案件状態変化（Gate承認等）を3名へ知らせるdesknet's NEO の標準通知／メール通知不要通知先はNEOで決定済み
② AppSuiteの案件情報をKnowledge（Notion）へ反映人間が承認結果を転記 or AIが下書き→人間確認不要双方向リアルタイム同期は「やりたい場合」に追加判断
③ AI壁打ち結果をNotion Idea DB／案件台帳へ登録AIが下書き→人間レビュー→登録不要自動登録は任意（後述の「強化したい場合」）
④ 承認フロー完了を通知・記録desknet's NEO Workflow の通知機能不要承認は必ずNEO内で完結し、結果をAppSuiteへ反映
⑤ LightblueがNotionのKnowledgeを参照（RAG）Lightblue標準機能（プラン内）不要Q6：ビジネスプランで可能かをベンダー確認
⑥ NEOの承認結果をAppSuiteのGate状態へ反映手動転記（初期）→ 自動化したい場合はAPI/iPaaS（将来）不要（初期）自動化は任意（下記4.3）
判定：基盤（案件管理フロー）の初期構築では、自前アプリ（外部受信サーバ・コード開発）は不要。

4.3 「Webhookが必要なとき」と「自動化を強化したい場合」に追加するもの

ご方針（Q4）：GitHub等はWebhookが必要なときのみ利用。API接続としてWebhookが必要と判断した箇所は都度指摘する。

本計画書で現時点に判断できる範囲では、初期構築で必須のWebhookはない。ただし、以下の「やりたいこと」が発生した時点でWebhook／API連携が必要になる（その時点で都度、接続構成を指摘する）。

やりたいことWebhook/APIが必要になる接続（例）追加するもの
NEO承認 → AppSuite Gate状態を自動更新 → 3名へ通知desknet's NEO API ⇔ Webhook ⇔ AppSuite／通知ノーコード連携基盤（iPaaS）or Webhook受信サーバ
NEO／AppSuite の状態変化をNotionへ自動反映desknet's NEO API ⇔ Webhook ⇔ Notion（またはAppSuite API ⇔ Webhook ⇔ Notion）iPaaS or Webhook受信サーバ
AppSuite ⇄ Knowledge（Notion） の双方向リアルタイム同期AppSuite API ⇔ Webhook ⇔ Notion APIAPI連携・Webhookの設計
監視基盤（自前Web）が各SaaSの状態を受け取る各SaaS API ⇔ Webhook ⇔ 監視基盤監視基盤側のWebhook受信機能（別途計画・4.4）
推奨：最初は「NEO通知＋人間による確認・転記」で回し、運用で「ここは自動化したい」が明確になった箇所だけ、上記の接続を追加する。Webhookが必要になった時点で、接続元（desknet's NEO API等）と接続先（AppSuite／Notion／監視基盤）の対応表とともに具体案を提示する。上記の接続を実装する際の受け皿として、AIDX開発基盤インフラ・ネットワーク構成設計書.htmlにVLAN170（INTEGRATION、Integration Hub、必要時追加）がPhase 3として設計済み。

  • AI回答の技術的妥当性を確認する工程があるか
  • 用語・操作が非エンジニア職掌（研究・技術職）にも分かりやすいか

6.3 IT/DX/AIシステム開発者
実装・運用の視点

  • 案件IDで全成果物を追跡できるか
  • 承認者・担当者の役割（SOD）に漏れや重複がないか
